## これは何か

Fhoe-Rail は **Windows** 上で動作する『崩壊：スターレイル』の**農作業（デイリー依頼の消化・素材集め）自動化スクリプト**です。

ゲームファイルやゲームコードを読み書きせず、人間と同じように操作します：**ゲーム画面をキャプチャ → テンプレートマッチング（OpenCV）で転送ポイント/インタラクションポイントを識別 → キーボード・マウスをシミュレート**して事前録音されたルートを実行します。すべての走図ルートはコミュニティが手動録音し、オープンソースで共有しています。

> **🌐 言語について**：画像認識テンプレート（`picture/`）はすべて**簡体字中国語クライアント**からキャプチャしたものです。ゲーム言語が異なるとボタン/ダイアログの文言も異なり、テンプレートマッチングが失敗するため、**現在は簡体字中国語クライアントのみ動作保証対象**です。
> 他の言語へ対応するには：対象言語のクライアントで `picture/` の**同名テンプレートをすべて**撮り直してください（ファイル名・解像度・キャプチャ範囲は既存と同一に、ファイル名は変更不可）。その後、実際に一巡して検証してください。PR を歓迎します。問題は [Fhoe-Rail-Maps](https://github.com/linruowuyin/Fhoe-Rail-Maps) の Discussions へどうぞ。

**これは何かではありません：**

- ❌ チート/改造ツールではない — プロセス注入・メモリやゲームファイルの改変は行いません
- ❌ クロスプラットフォームツールではない — Windows のみ対応（pywin32 / PyAutoGUI / PyGetWindow に依存）
- ❌ 商用製品ではない — 無料・オープンソース・学習交流のみ
- ⚠️ サードパーティスクリプトの使用には**アカウント停止リスク**があります。文末の[免責事項](#ライセンスと免責事項)をお読みください。

## クイックスタート

### 環境要件

| 項目 | 要件 |
| --- | --- |
| OS | Windows（Win32 API に依存） |
| 解像度 | 1920×1080（雲星鉄は全画面必須） |
| フレームレート | 60 FPS |
| Python | 3.11+（ソースから実行する場合。リリース版は exe 単体で不要） |
| ネットワーク | 任意（通知プッシュ・自動更新チェックに使用） |

### 実行上の注意

1. 録音されたキー操作 + 画像認識という性質上、ルートはコミュニティによる手動・公益録音です
2. スロット1は遠距離キャラクターにしてください。黄泉マップは黄泉、銀狼LV.999マップは銀狼LV.999を使用
3. 遠距離キャラは**成年モデル**で攻撃に移動がないものを推奨。少女モデルはマップに引っかかる可能性
4. 事前にすべての転送アンカーを解放し、識別を妨げるクエストを完了しておくこと（未処理だとマップに引っかかる可能性）
5. 未解放の仕掛け/クエストマーカーに注意
6. ブラックリスト設定：`--debug` で起動し、設定で禁止マップを追加（禁闭舱段が未解放なら「禁闭舱段」、绥园が未解放なら「绥园」を追加）
7. デフォルトのキーバインディングを変更しないこと
8. 画面にカバー（オーバーレイ）がないこと（ポップアップに注意）
9. 非自動戦闘状態でマウス・キーボードを操作しないこと

### 起動方法

| 方法 | 説明 |
| --- | --- |
| メニュー（推奨） | `1点这里.bat` または `Fhoe-Rail.bat` をダブルクリックし、メニューに従う |
| 設定不要 | `Fhoe-Rail.exe` を直接実行 |
| WebUI | `Start-WebUI.bat` をダブルクリック → http://127.0.0.1:8666 が自動で開く |
| ソースから | `pip install -r requirements.txt` 後、`python fhoe.py` |

### コマンドライン引数

| 引数 | 説明 |
| --- | --- |
| `--debug` | 3段階のマップ選択メニュー（設定含む） |
| `--dev` | `--debug` と同じだが、毎ラウンド自動で再選択 |
| `--white` | ホワイトリスト |
| `--record` | 新規マップの録音 |
| `--test` | テストモード |
| `--config` | 設定モード |
| `--map <ID>` | 単一マップのみ実行（例：`3-5_1`） |
| `--range <start> <end>` | リスト順に開始から終了まで（両端含む、例：`3-5_1 3-5_2`） |
| `--map-version <名>` | 一時的にバージョン指定（例：`HuangQuan`） |
| `--webui-server` | 内蔵 WebUI を起動（ポート 8666） |

**制約**：`--range` の開始と終了は同じマップバージョンで、終了が開始より前であってはなりません。

### 既知の制限

- 画像認識はキャプチャに依存するため、カバー（ポップアップ/他ウィンドウ/マウスヒント）があると識別に影響
- 一部の画面では全画面認識できないため、非全画面で再試行してください
- 使用にはアカウント停止リスクが伴うため、自己判断で評価してください

## WebUI コントロールパネル

内蔵のローカル WebUI（サードパーティ依存なし、Python 標準ライブラリのみ）：

- **起動**：`Start-WebUI.bat` をダブルクリック → 自動で管理者権限を要求し、http://127.0.0.1:8666 を開く
- **重複起動**：ポートが自前の WebUI に占有されている場合、新インスタンスが旧インスタンスを正常終了させてから引き継ぐ。他プログラムが占有している場合はエラーのみ（プロセスは殺さない）
- **指揮台**：実行状態と統計（戦闘回数 / 総所要時間 / 疾走節約 / カクつき）＋実行ごとのマップ消化数と所要時間を自動集計
- **実行制御**：デフォルト / ホワイトリスト / 単一マップ / レンジ / 開発者単一マップ / 録音 / 依存インストール の7モードをリアルタイム出力
- **マップ図鑑**：バージョン/惑星で全ルートを閲覧。名前/番号/作者で検索可能
- **マップエディター**：ブラウザ上でマップを新規作成・編集——アクションキーと画像 stem は自動補完、保存前に書式を自動検証し、不正な内容は書き込みを拒否
- **パラメータ設定**：`config.json` の全項目を可視化編集。保存/コピー/ダウンロード対応
- **航行ログ**：リアルタイム表示
- **新マップ注意**：新マップの注意事項画像を閲覧

## マップ

### マップバージョン

マップは JSON ファイルとしてバージョンディレクトリに編成されています（`map/<バージョン>/`）。現在の内蔵バージョン：

| バージョン | 説明 |
| --- | --- |
| `default` | デフォルトマップ、大半の遠距離キャラに対応 |
| `default_lite` | 簡易版マップ |
| `technique` | 誰もメンテナンスしていない（<del>紫の秘技が多く、戦闘中も多用</del>） |
| `HuangQuan` | 黄泉専用マップ、秘技零食を自分で用意する必要あり |
| `SilverWolfLv999` | 銀狼 LV.999 専用マップ（黄泉マップから変換、E秘技は使用しない） |
| `reward` | 特殊アイテム受け取りルート |

> **走図モデル分類**：一部キャラは体型の理由で引っかかることがあります。遠距離キャラは**成年モデル**かつ攻撃に移動がないものを優先。少女モデルはマップに引っかかる可能性。

### マップの選択

`--debug` モード（または `自选地图.bat`）で実行し、【設定】を選択すると対応マップを選択できます。

### 新規マップの録音

> [@AlisaCat](https://github.com/AlisaCat-S) に感謝します。

**操作制限：**

- マウスで視点を動かすのは禁止
- 録音中は**一度に1つの有効なキーのみ**押せる（複数同時押し不可）
- 録音対応キー：`W`/`S`/`A`/`D`（移動）、`F`（インタラクション）、`R`（ペナコニーの夢泡橋）、`E`（秘技、黄泉マップの敵討伐で多用）、`X`（戦闘開始）、マウス右クリック（障害物破壊 / 疾走後の壁当たりでダッシュ解除）、`v`（N秒待機）
- その他のキーが必要な場合は設定ファイルを手動変更

**録音ルール：**

- スクリプトはキーが押された時間と視点移動のみ記録し、**停止時間は記録しない**
- 正確さのため、1キーずつゆっくり録音することを推奨

**録音完了：** `F9` で停止・保存し、`output(時間).json` を生成。

**出力と設定：**

1. `output(時間).json` を対象マップの JSON ファイル名にリネーム
2. 転送ポイントのスクリーンショットをリネームして `picture` フォルダに保存
3. 新マップは [Fhoe-Rail-Maps](https://github.com/linruowuyin/Fhoe-Rail-Maps) リポジトリにコミット（CI 検証後に自動マージ）、または管理者に依頼

**スクリーンショット要件：**

- テキスト認識のため、重複した文言を避ける（例：「支援舱段」「禁闭舱段」は支援と禁闭のみを切り取る。そうしないと認識できず誤クリック）
- 将来の多言語対応のため、できるだけテキストを切り取らない
- 範囲はできるだけ小さく（画像が増えるため、範囲を適宜縮小）

### マップ JSON 形式

マップは **v1（旧形式）** と **v2（推奨）** の 2 つの記述形式に対応：トップレベルに `"v": 2` を書くと v2、省略すると v1 として解析（完全互換）。実行時は両者等価で、バリデーターは両形式に有効。

**v2（推奨）**——画像参照を名前付きフィールドに、行内コメントと連打折りたたみに対応：

```json
{
    "v": 2,
    "name": "乌拉乌拉-1",
    "author": "Starry-Wind",
    "start": [
        {"map": 1},                                   // アクションキーは v1 と同一
        {"img": "orientation_1", "delay": 1.5},       // v1 の {"picture\\orientation_1.jpg": 1.5} と等価
        {"img": "transfer", "delay": 1.5, "wait": 3}  // wait：クリック後、画面が 3 秒静止するまで待つ（読み込みの遅い環境で安定）
    ],
    "map": [
        {"a": 0.2, "rep": 3}                          // v1 の {"a": 0.2} を 3 回書くのと等価
    ]
}
```

フィールド：`img` 画像リソース名（パスと拡張子なし、`start` のみ）· `delay` クリック後の待機秒数（既定 0.8）· `rep` 繰り返し回数 · `c` 行内コメント（実行時無視）· `wait` クリック後、画面が静止するまで待機（秒、0-30、任意）。

**v1（旧形式・完全互換）**：

```json
{
    "name": "乌拉乌拉-1",                     // マップ JSON ファイル名は 1-1_1.json
    "author": "Starry-Wind",                 // 作者名（第2作者は第1作者を上書きできない）
    "start": [                                 // 開始時の転送マップ操作ステップ
        {"map": 1},                            // m キーでマップを開く
        {"picture\\orientation_1.jpg": 1.5}, // orientation_1.jpg を認識し、画像中央にマウスを移動してキーを押す
        {"picture\\map_1.jpg": 2},           // エリア名に対応する画像（例："乌拉乌拉"）
        {"picture\\map_1_point_1.jpg": 1.5}, // 最初の転送ポイントの画像
        {"picture\\transfer.jpg": 1.5},      // "転送"文字の画像
        {"space": 1},                          // space キーを押す
        {"b": 1},                              // b キーを押す
        {"await": 5}                           // 5秒待機
    ]
}
```


> 完全なフィールド定義と検証ルールは [docs/MAP_FORMAT.md](./docs/MAP_FORMAT.md)。WebUI エディターは保存前に両形式を自動検証します。
### メイン画面検出

各マップが `map` のステップを開始する前に、スクリプトは固定で `back_to_main` を1回実行します（`start` 末尾に `{"main": 1}` を書くのと同等ですが、マップ側で書く必要はありません）：

1. まずメイン画面（左上の電球アイコン）を識別
2. メイン画面でない場合は `ESC` で戻る。「放弃游玩しますか？」確認ダイアログは先に閉じる。最大120秒待機し、タイムアウト時はこのラウンドを終了してゲーム画面の確認を促す

つまり `map` の最初のステップの前提は2つ：**現在メイン画面にいること**、かつ**この状態がメイン画面から `ESC` で到達可能であること**。マップの編集・録音時は注意：

- 「転送後の残留ダイアログ / メニュー / 戦闘」を最初のステップの前提にしない。これらを処理する場合は `start` の末尾（メイン画面検出の前）に置くか、`ESC` でメイン画面に戻れることを確認してから `map` に書く
- `map` の先頭で `{"main": 1}` を重複して書く必要はない。`{"esc": 1}` も書かないこと — この時点では既にメイン画面にいるため、余分な `ESC` は ESC メニューを開き、以降のステップがメニュー内から始まってしまう

## キーバインディング

| キー | マッピング |
| --- | --- |
| `other` | リストにない任意のキーは移動キー。後ろの数字は押す時間の長さ |
| `x` | 戦闘開始。map マッピングは `fighting=1` |
| マウス左ボタン | 障害物を攻撃。map マッピングは `fighting=2` |
| `f` | インタラクションキー。後ろの数字は F キーを押した後の待機時間（デフォルト15秒） |
| `r` / `space` | インタラクションキー。後ろの数字は押す回数（間隔はランダム） |
| `shutdown` | シャットダウンフラグ。キー値は無意味。制御スイッチは設定ファイル |
| `mouse_move` | 視点回転。数値計算が複雑なため（デバイスごとに異なる）廃止済み |
| `scroll` | マウスホイールスクロール値。同様に複雑なため未使用 |
| `e` | 値が1の場合、秘技を使用し通常攻撃を追加 |
| `e` | 値が2の場合、秘技のみ使用。強化型秘技キャラ向け |
| `esc` | 値が1の場合のみ意味があり、Esc キーを1回押すのと同じ |
| `v` | N秒待機。map マッピングは `await=N` 秒 |

### アーキテクチャとレイヤリング

プロジェクトは **core → drivers → vision → flows → ui** のレイヤリングで、依存方向は単方向（`tests/test_architecture.py` が強制検証）。

重要な制約（詳細は `CLAUDE.md` §3）：

- 時間・入力・画面・状態・構造・リソース更新にハードルール
- マップ JSON は v1/v2 の二重記述形式に対応、実行時は v1 に統一正規化（docs/MAP_FORMAT.md）
- プリセットとデッドコードのクリーンアップに関する専用の約束
- マップ実行契約、ESC 前の画面修復に関する明確な約束

### テストと CI

**テスト**：`pytest`（全モック、ゲームウィンドウ不要。`xfail` は記録済みの実欠陥）に加え、3つの静的検証ツール：

| ツール | 役割 |
| --- | --- |
| `tools/validate_maps.py` | マップ JSON 構造検証、エラー時 exit 1 |
| `tools/validate_pictures.py` | 画像ファイル名のグローバル一意性 + `picture` 参照の解決可能性 |
| `tools/migrate_maps_v2.py` | v1 → v2 マップ形式移行（既定ドライラン、`--write` で書き込み） |
| `tools/format_maps.py --base <ref>` | R22 書き込みフォーマット検証、今回変更したマップのみ対象 |

**CI**（`.github/workflows/run.yml`、`windows-latest` + Python 3.11.5）：

- **test** ジョブ：pytest + マップ検証 + 画像検証 + フォーマット検証
- **build** ジョブ：PyInstaller で `Fhoe-Rail.exe` と `Start-WebUI.exe` をパッケージ、各 `.bat` を生成、リソースを `dist` にコピー、タグ時に `softprops/action-gh-release` で `Fhoe-Rail.zip` をリリースし `version.txt` を書く

トリガー：任意のブランチ/タグへの push（`paths` は `**.py` + `map/**.json` に制限。タグ push は `paths` フィルタの影響を受けない）。`fetch-depth: 0`（浅いクローンではベースラインを取得できない）。

### 貢献ガイド

最適化 / 新バージョンのルートマップ、およびコード改善の貢献を歓迎します：

- 新マップ：録音後、[新規マップの録音](#新規マップの録音)の仕様に従って JSON + スクリーンショットを生成し、[Fhoe-Rail-Maps](https://github.com/linruowuyin/Fhoe-Rail-Maps) リポジトリにコミット（CI 検証）、または管理者に依頼
- コード：`CLAUDE.md` の開発順序（実現可能性プローブ → 契約とリソース → 純ロジックの厳密な TDD → 検出器のゴールデンイメージ → オーケストレーションのモック仮想クロック → リプレイのエンドツーエンド）に従い、ローカル `pytest` + 3つの検証ツールを通過させる
- コミット前に完全な CI を実行（ローカルでは `tools/` のスクリプトで再現可能）

## 全自動農作業（上級）

アイデアのみ提供：

1. PC の BIOS で**通電時自動起動**を有効化
2. **スマートプラグ**×1（例：米家スマートプラグ3）を用意し、電源をタイマーでオン（ピーク/オフピーク電力のオフピーク時間を推奨）
3. スターレイルのゲームショートカット（ランチャーではない）を `map` フォルダとスタートアップフォルダに配置
4. 「終了後にシャットダウン」を有効化

**欠点**：アップデートやネットワークのカクつきでフリーズする可能性（スクリプトはクリック対策を設計していない）。電源オフのタイマーも設定することを推奨（時間は全マップ実行後のログ計測を参照）。
