## 이것은 무엇인가

Fhoe-Rail은 **Windows**에서 작동하는 《붕괴: 스타레일》 **농작업(일일 의뢰 소화·재료 수집) 자동화 스크립트**입니다.

게임 파일이나 게임 코드를 읽고 쓰지 않고, 사람과 같은 방식으로 조작합니다: **게임 화면 캡처 → 템플릿 매칭(OpenCV)으로 이동 포인트/상호작용 포인트 식별 → 키보드·마우스 시뮬레이션**으로 미리 녹음된 루트를 실행합니다. 모든 맵 루트는 커뮤니티가 수동으로 녹음하고 오픈소스로 공유합니다.

> **🌐 언어 안내**: 이미지 인식 템플릿(`picture/`)은 모두 **간체 중국어 클라이언트**에서 캡처한 것입니다. 게임 언어가 다르면 버튼/대화상자 문구도 달라져 템플릿 매칭이 실패하므로, **현재 간체 중국어 클라이언트만 지원**합니다.
> 다른 언어를 지원하려면: 해당 언어 클라이언트로 **동일한 이름의 템플릿 전부**를 다시 캡처해 예약 디렉터리 `picture_en/` 에 넣으세요(영어 예시. 다른 언어는 `picture_<언어 코드>/`). 파일명·해상도·캡처 영역은 `picture/` 기존 템플릿과 동일해야 합니다. 참고: 예약 디렉터리의 템플릿은 **아직 프로그램에 로드되지 않습니다**——다국어 로드 지원과 함께 활성화됩니다. 자세한 규칙은 [picture_en/README.md](../picture_en/README.md) 를 참고하세요. PR 을 환영합니다. 문제는 [Fhoe-Rail-Maps](https://github.com/linruowuyin/Fhoe-Rail-Maps) Discussions 에 남겨 주세요.

**이것은 무엇이 아닌가:**

- ❌ 치트/변조 도구가 아님 — 프로세스 주입·메모리나 게임 파일 수정은 하지 않습니다
- ❌ 크로스플랫폼 도구가 아님 — Windows 전용(pywin32 / PyAutoGUI / PyGetWindow 의존)
- ❌ 상용 제품이 아님 — 무료·오픈소스·학습 교류 전용
- ⚠️ 서드파티 스크립트 사용에는 **계정 정지 위험**이 있습니다. 문서 끝의 [면책 조항](#라이선스와-면책-조항)을 읽어 주세요.

## 빠른 시작

### 환경 요구 사항

| 항목 | 요구 사항 |
| --- | --- |
| OS | Windows(Win32 API 의존) |
| 해상도 | 1920×1080(클라우드 스타레일은 전체 화면 필수) |
| 프레임레이트 | 60 FPS |
| Python | 3.11+(소스에서 실행 시. 릴리스 버전은 exe 단독으로 불필요) |
| 네트워크 | 선택(알림 푸시·자동 업데이트 확인에 사용) |

### 실행 시 주의사항

1. 녹음된 키 조작 + 이미지 인식이라는 특성상, 루트는 커뮤니티 수동·공익 녹음입니다
2. 슬롯 1은 원거리 캐릭터로 하세요. 황천 맵은 황천, 은랑 LV.999 맵은 은랑 LV.999 사용
3. 원거리 캐릭터는 **성인 모델**이며 공격에 이동이 없는 것을 권장. 소녀 모델은 맵에 걸릴 수 있음
4. 사전에 모든 이동 앵커를 해금하고 식별을 방해하는 퀘스트를 완료할 것(미처리 시 맵에 걸릴 수 있음)
5. 미해금 장치/퀘스트 마커 주의
6. 블랙리스트 설정: `--debug`로 시작해 설정에서 금지 맵 추가(금폐 창단 미해금 시「금폐 창단」, 수원 미해금 시「수원」 추가)
7. 기본 키 바인딩을 변경하지 말 것
8. 화면에 커버(오버레이)가 없어야 함(팝업 주의)
9. 비자동 전투 상태에서 마우스·키보드를 조작하지 말 것

### 실행 방법

| 방법 | 설명 |
| --- | --- |
| 메뉴(권장) | `1点这里.bat` 또는 `Fhoe-Rail.bat` 더블 클릭 후 메뉴 따르기 |
| 설정 불필요 | `Fhoe-Rail.exe` 직접 실행 |
| WebUI | `Start-WebUI.bat` 더블 클릭 → http://127.0.0.1:8666 자동 열림 |
| 소스에서 | `pip install -r requirements.txt` 후 `python fhoe.py` |

### 커맨드라인 인수

| 인수 | 설명 |
| --- | --- |
| `--debug` | 3단계 맵 선택 메뉴(설정 포함) |
| `--dev` | `--debug`와 같지만 매 라운드 자동 재선택 |
| `--white` | 화이트리스트 |
| `--record` | 새 맵 녹음 |
| `--test` | 테스트 모드 |
| `--config` | 설정 모드 |
| `--map <ID>` | 단일 맵만 실행(예: `3-5_1`) |
| `--range <start> <end>` | 목록 순서대로 시작~끝(양 끝 포함, 예: `3-5_1 3-5_2`) |
| `--map-version <이름>` | 임시로 버전 지정(예: `HuangQuan`) |
| `--webui-server` | 내장 WebUI 시작(포트 8666) |

**제약**: `--range`의 시작과 끝은 같은 맵 버전이어야 하며, 끝이 시작보다 앞서면 안 됩니다.

### 알려진 제한 사항

- 이미지 인식은 캡처에 의존하므로 커버(팝업/다른 창/마우스 힌트)가 있으면 식별에 영향
- 일부 화면은 전체 화면 인식이 안 되므로 비전체 화면으로 재시도하세요
- 사용 시 계정 정지 위험이 따르므로 자체 판단으로 평가하세요

## WebUI 컨트롤 패널

내장 로컬 WebUI(서드파티 의존성 없음, Python 표준 라이브러리만):

- **시작**: `Start-WebUI.bat` 더블 클릭 → 자동으로 관리자 권한 요청 후 http://127.0.0.1:8666 열기
- **중복 시작**: 포트가 자체 WebUI에 점유된 경우 새 인스턴스가 기존 인스턴스를 정상 종료시킨 뒤 인계. 다른 프로그램이 점유하면 에러만(프로세스는 죽이지 않음)
- **지휘대**: 실행 상태와 통계(전투 횟수 / 총 소요 시간 / 대시 절약 / 끊김) + 실행별 맵 소화 수와 소요 시간 자동 집계
- **실행 제어**: 기본 / 화이트리스트 / 단일 맵 / 레인지 / 개발자 단일 맵 / 녹음 / 의존성 설치 7모드 실시간 출력
- **맵 도감**: 버전/행성별 전체 루트 열람. 이름/번호/작성자 검색 가능
- **맵 편집기**: 브라우저에서 맵 신규 작성/편집——액션 키와 이미지 stem 자동 완성, 저장 전 형식 자동 검증, 불법 항목은 기록 거부
- **파라미터 설정**: `config.json` 전체 항목 시각화 편집. 저장/복사/다운로드 지원
- **항해 로그**: 실시간 표시
- **새 맵 주의**: 새 맵 주의사항 이미지 열람

## 설정

| `allow_snack_buy` | `false` | 비기 간식 합성 재료 구매 허용 |
| `allow_memory_token` | `false` | 옹파로스 기억 토큰 획득 허용 |
| `allowlist_mode_once` | `false` | 이번만 화이트리스트 |
| `auto_shutdown` | `0` | 농작업 종료 시 시스템 동작: 0=없음 / 1=종료 / 2=로그오프 / 3=지정 프로세스 종료 |

| `webhook_url` | — | 범용 Webhook 알림 대상 |
| `notify_enabled` | `false` | 알림 활성화 여부 |
| `notify_channel` | — | 채널(windows 데스크톱 알림 / serverchan / pushplus / telegram / dingtalk 등) |
| `notify_key` | — | 채널 키 |
| `notify_chat_id` | — | 알림 대상 파라미터(예: Telegram chat_id) |
| `notify_params` | — | 채널 고급 파라미터 JSON |
| `notify_on_start` | `false` | 시작 시 알림 |
| `notify_on_end` | `false` | 완료 시 알림(통계 포함) |
| `notify_on_error` | `false` | 오류 시 알림 |

## 맵

### 맵 버전

맵은 JSON 파일로 버전 디렉터리에 정리되어 있습니다(`map/<버전>/`). 현재 내장 버전:

| 버전 | 설명 |
| --- | --- |
| `default` | 기본 맵, 대부분 원거리 캐릭터 대응 |
| `default_lite` | 간이 버전 맵 |
| `technique` | 유지보수 안 됨(<del>보라 비기가 많고 전투 중에도 자주 사용</del>) |
| `HuangQuan` | 황천 전용 맵, 비기 간식 직접 준비 필요 |
| `SilverWolfLv999` | 은랑 LV.999 전용 맵(황천 맵에서 변환, E비기 사용 안 함) |
| `reward` | 특수 아이템 획득 루트 |

> **주행 모델 분류**: 일부 캐릭터는 체형 때문에 걸릴 수 있습니다. 원거리 캐릭터는 **성인 모델**이며 공격에 이동이 없는 것을 우선. 소녀 모델은 맵에 걸릴 수 있음.

### 맵 선택

`--debug` 모드(또는 `自选地图.bat`)로 실행하고 【설정】을 선택하면 해당 맵을 선택할 수 있습니다.

### 새 맵 녹음

> [@AlisaCat](https://github.com/AlisaCat-S)님께 감사드립니다.

**조작 제한:**

- 마우스로 시점을 움직이는 것 금지
- 녹음 중에는 **한 번에 유효한 키 하나만** 누를 수 있음(여러 키 동시 입력 불가)
- 녹음 지원 키: `W`/`S`/`A`/`D`(이동), `F`(상호작용), `R`(페나코니의 꿈방울 다리), `E`(비기, 황천 맵의 적 토벌에서 자주 사용), `X`(전투 시작), 마우스 오른쪽 클릭(장애물 파괴 / 대시 후 벽 충돌로 대시 해제), `v`(N초 대기)
- 그 외 키가 필요하면 설정 파일을 수동 변경

**녹음 규칙:**

- 스크립트는 키를 누른 시간과 시점 이동만 기록하고, **정지 시간은 기록하지 않음**
- 정확성을 위해 키를 하나씩 천천히 녹음 권장

**녹음 완료:** `F9`로 정지·저장하고 `output(시간).json` 생성.

**출력과 설정:**

1. `output(시간).json`을 대상 맵의 JSON 파일 이름으로 변경
2. 이동 포인트 스크린샷을 `picture` 폴더에 저장(이름 변경)
3. 새 맵은 [Fhoe-Rail-Maps](https://github.com/linruowuyin/Fhoe-Rail-Maps) 리포지토리에 커밋(CI 검증 후 자동 병합)하거나 관리자에게 요청

**스크린샷 요구 사항:**

- 텍스트 인식을 위해 중복된 문구를 피할 것(예: 「지원 창단」「금폐 창단」은 지원과 금폐만 잘라내기. 그렇지 않으면 인식이 안 되고 오클릭)
- 향후 다국어 대응을 위해 가능한 한 텍스트를 잘라내지 말 것
- 범위는 최대한 작게(이미지가 늘어나므로 범위를 적절히 축소)

### 맵 JSON 형식

맵은 **v1(구 형식)** 과 **v2(권장)** 두 가지 작성 형식을 지원: 최상위에 `"v": 2` 를 쓰면 v2, 없으면 v1 로 파싱(완전 호환). 실행 시 두 형식은 등가이며 검증기는 둘 다 적용.

**v2(권장)**——이미지 참조를 이름 붙은 필드로, 행 내 주석과 연타 접기 지원:

```json
{
    "v": 2,
    "name": "乌拉乌拉-1",
    "author": "Starry-Wind",
    "start": [
        {"map": 1},                                   // 액션 키는 v1 과 동일
        {"img": "orientation_1", "delay": 1.5},       // v1 의 {"picture\\orientation_1.jpg": 1.5} 과 등가
        {"img": "transfer", "delay": 1.5, "wait": 3}  // wait: 클릭 후 화면이 3 초간 정지할 때까지 대기(로딩이 느린 환경에 안정)
    ],
    "map": [
        {"a": 0.2, "rep": 3}                          // v1 의 {"a": 0.2} 를 3 번 쓴 것과 등가
    ]
}
```

필드: `img` 이미지 리소스 이름(경로/확장자 없음, `start` 전용) · `delay` 클릭 후 대기 초(기본 0.8) · `rep` 반복 횟수 · `c` 행 내 주석(실행 시 무시) · `wait` 클릭 후 화면이 정지할 때까지 대기(초, 0-30, 선택).

**v1(구 형식, 완전 호환):**

```json
{
    "name": "乌拉乌拉-1",                     // 맵 JSON 파일 이름은 1-1_1.json
    "author": "Starry-Wind",                 // 작성자 이름(제2 작성자는 제1 작성자를 덮어쓸 수 없음)
    "start": [                                 // 시작 시 이동 맵 조작 단계
        {"map": 1},                            // m 키로 맵 열기
        {"picture\\orientation_1.jpg": 1.5}, // orientation_1.jpg를 인식하고 이미지 중앙으로 마우스 이동 후 키 입력
        {"picture\\map_1.jpg": 2},           // 지역 이름에 해당하는 이미지(예: "乌拉乌拉")
        {"picture\\map_1_point_1.jpg": 1.5}, // 첫 번째 이동 포인트 이미지
        {"picture\\transfer.jpg": 1.5},      // "이동" 문자 이미지
        {"space": 1},                          // space 키 입력
        {"b": 1},                              // b 키 입력
        {"await": 5}                           // 5초 대기
    ]
}
```


> 전체 필드와 검증 규칙은 [docs/MAP_FORMAT.md](./docs/MAP_FORMAT.md). WebUI 편집기는 저장 전 두 형식을 자동 검증합니다.
### 메인 화면 감지

각 맵이 `map` 단계를 시작하기 전에, 스크립트는 고정으로 `back_to_main`을 1회 실행합니다(`start` 끝에 `{"main": 1}`을 쓰는 것과 동일하지만 맵 쪽에서 쓸 필요는 없음):

1. 먼저 메인 화면(좌상단 전구 아이콘)을 식별
2. 메인 화면이 아니면 `ESC`로 복귀. 「플레이 그만둘까요?」 확인 다이얼로그는 먼저 닫기. 최대 120초 대기, 타임아웃 시 이번 라운드 종료 후 게임 화면 확인 요청

즉 `map`의 첫 단계 전제는 둘: **현재 메인 화면에 있을 것**, 그리고 **이 상태가 메인 화면에서 `ESC`로 도달 가능할 것**. 맵 편집·녹음 시 주의:

- 「이동 후 잔류 다이얼로그 / 메뉴 / 전투」를 첫 단계 전제로 삼지 말 것. 처리하려면 `start` 끝(메인 화면 감지 전)에 두거나, `ESC`로 메인 화면에 복귀 가능한지 확인 후 `map`에 쓸 것
- `map` 시작에 `{"main": 1}`을 중복해서 쓸 필요 없음. `{"esc": 1}`도 쓰지 말 것 — 이 시점에는 이미 메인 화면에 있으므로, 불필요한 `ESC`는 ESC 메뉴를 열고 이후 단계가 메뉴 안에서 시작됨

## 키 바인딩

| 키 | 매핑 |
| --- | --- |
| `other` | 목록에 없는 임의의 키는 이동 키. 뒤 숫자는 누르는 시간 길이 |
| `x` | 전투 시작. map 매핑은 `fighting=1` |
| 마우스 왼쪽 버튼 | 장애물 공격. map 매핑은 `fighting=2` |
| `f` | 상호작용 키. 뒤 숫자는 F 키를 누른 후 대기 시간(기본 15초) |
| `r` / `space` | 상호작용 키. 뒤 숫자는 누르는 횟수(간격은 랜덤) |
| `shutdown` | 종료 플래그. 키 값은 무의미. 제어 스위치는 설정 파일 |
| `mouse_move` | 시점 회전. 수치 계산이 복잡해(기기마다 다름) 폐기됨 |
| `scroll` | 마우스 휠 스크롤 값. 역시 복잡해 미사용 |
| `e` | 값이 1이면 비기를 사용하고 일반 공격 추가 |
| `e` | 값이 2이면 비기만 사용. 강화형 비기 캐릭터용 |
| `esc` | 값이 1일 때만 의미 있으며 Esc 키 1회 입력과 동일 |
| `v` | N초 대기. map 매핑은 `await=N`초 |

### 아키텍처와 레이어링

프로젝트는 **core → drivers → vision → flows → ui** 레이어링이며 의존 방향은 단방향(`tests/test_architecture.py`가 강제 검증).

중요한 제약(자세한 내용은 `CLAUDE.md` §3):

- 시간·입력·화면·상태·구조·리소스 업데이트에 하드 룰
- 맵 JSON 은 v1/v2 이중 작성 형식 지원, 실행 시 v1 로 통일 정규화(docs/MAP_FORMAT.md)
- 프리셋과 데드 코드 정리에 관한 전용 약속
- 맵 실행 계약, ESC 전 화면 복구에 관한 명확한 약속

### 테스트와 CI

**테스트**: `pytest`(전부 목, 게임 창 불필요. `xfail`은 기록된 실제 결함)에 더해 3개 정적 검증 도구:

| 도구 | 역할 |
| --- | --- |
| `tools/validate_maps.py` | 맵 JSON 구조 검증, 오류 시 exit 1 |
| `tools/validate_pictures.py` | 이미지 파일명 전역 유일성 + `picture` 참조 해결 가능성 |
| `tools/migrate_maps_v2.py` | v1 → v2 맵 형식 마이그레이션(기본 드라이런, `--write` 로 기록) |
| `tools/format_maps.py --base <ref>` | R22 쓰기 포맷 검증, 이번에 변경한 맵만 대상 |

**CI**(`.github/workflows/run.yml`, `windows-latest` + Python 3.11.5):

- **test** 잡: pytest + 맵 검증 + 이미지 검증 + 포맷 검증
- **build** 잡: PyInstaller로 `Fhoe-Rail.exe`와 `Start-WebUI.exe` 패키징, 각 `.bat` 생성, 리소스를 `dist`에 복사, 태그 시 `softprops/action-gh-release`로 `Fhoe-Rail.zip` 릴리스하고 `version.txt` 작성

트리거: 임의 브랜치/태그로의 push(`paths`는 `**.py` + `map/**.json`으로 제한. 태그 push는 `paths` 필터 영향 없음). `fetch-depth: 0`(얕은 클론에서는 베이스라인을 얻을 수 없음).

## 완전 자동 농작업(고급)

아이디어만 제공:

1. PC BIOS에서 **통전 시 자동 시작** 활성화
2. **스마트 플러그**×1(예: 미가 스마트 플러그 3) 준비, 타이머로 전원 켜기(피크/오프피크 전력의 오프피크 시간 권장)
3. 스타레일 게임 바로가기(런처 아님)를 `map` 폴더와 시작 폴더에 배치
4. 「종료 후 종료」 활성화

**단점**: 업데이트나 네트워크 끊김으로 프리즈할 수 있음(스크립트는 클릭 대책을 설계하지 않음). 전원 끄기 타이머도 설정 권장(시간은 전체 맵 실행 후 로그 측정 참조).
